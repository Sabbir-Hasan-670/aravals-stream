# Facebook capability audit (24 September 2026)

Source of truth: Meta's current Graph API v26.0 and Live Video API documentation. This file records the decision before the Facebook implementation.

| Capability | Current official evidence | Aravals decision |
| --- | --- | --- |
| Browser login in a standalone desktop app | [Manual login flow](https://developers.facebook.com/docs/facebook-login/guides/advanced/manual-flow/) describes a desktop WebView token redirect. Code exchange and token verification require a server-held App Secret; the secret must not ship in client code. | `UnsupportedByCurrentMetaApi` for this desktop-only architecture. Do not claim a secure native OAuth connection. Allow an advanced user to import an official user access token issued for their own Meta app, stored with DPAPI. |
| Pages and Page tokens | [User Accounts edge](https://developers.facebook.com/docs/graph-api/reference/user/accounts/) returns Pages and assigned tasks; [long-lived token guide](https://developers.facebook.com/docs/facebook-login/guides/access-tokens/get-long-lived/) explains Page tokens derived from a user token. | Supported for authorized tokens. Keep Page token separate from user token, both in DPAPI. Never perform App Secret exchange locally. |
| Page Live creation and ingest | [Page Live Videos edge](https://developers.facebook.com/docs/graph-api/reference/page/live_videos/) permits `POST /{page-id}/live_videos`, returns `secure_stream_url`, and documents `UNPUBLISHED`/`LIVE_NOW`/scheduled states. [Live Video API overview](https://developers.facebook.com/docs/live-video-api/) requires Live Video API App Review and Page `pages_manage_posts` and `pages_read_engagement` permissions. | Supported only for an authorized Page/app. Request `LIVE_NOW`, store ingest credentials with DPAPI, then use existing StreamingOutput. Do not create two native outputs for one Page. Graph creation alone is never treated as encoder progress or verified platform Live. |
| Personal profile and Groups | Live Video API overview mentions these account types, but their permissions and runtime access differ. | `UnsupportedByCurrentMetaApi` in Aravals native flow until documented and tested. Manual RTMP remains. |
| Scheduled Live | Page Live Videos reference lists scheduled states and `event_params`; permission and lifecycle details need live validation. | Not exposed in 0.14. Manual schedule via Facebook remains possible. |
| Live comment reading | [Live Video Comments edge](https://developers.facebook.com/docs/graph-api/reference/live-video/comments/) supports GET and recommends reverse chronological polling. | Poll an authorized Page broadcast conservatively with deduplication. Show errors separately from transport. |
| Live comment posting | [Comment reference](https://developers.facebook.com/docs/graph-api/reference/comment/) documents `POST /{video-id}/comments`. | Attempt only with authorized Page token; surface permission errors. |
| Real-time webhook events | Webhooks need a public server callback. | No direct webhook receiver in desktop-only build. No reactions, Stars, follower, or share claims. |
| Viewer count | Not established from the reviewed Page Live Videos edge. | Display `—` until verified from an official field. |
| Long-lived token refresh | [Meta guide](https://developers.facebook.com/docs/facebook-login/guides/access-tokens/get-long-lived/) requires an App Secret and server-side exchange; user tokens usually expire in about 60 days. | Do not auto-refresh in desktop. Detect expiry/permission loss and request a new token. |
| App Review and development mode | Live Video API overview explicitly requires App Review. | Native Page features are conditional on app review/permissions. Development app access is limited to app-role users. |

Graph API version is pinned to `v26.0`. Native Page setup through an imported token is an advanced developer workflow, not Facebook Login. The existing Facebook Manual RTMP destinations are never converted.

Phase 20B (1 October 2026): Relay GET challenge and signed `page` feed/live_videos fixture verification/normalization are supported. Live reactions, Stars, followers and share alert semantics remain **UNSUPPORTED BY CURRENT PROVIDER INTEGRATION/API** in this integration. Generic feed changes enter the existing event bus as Custom events; they do not imply shares. Real Meta callback delivery and application review/permissions remain unverified. Official Meta webhook reference endpoints returned HTTP 429 during the Phase 20B contract check.
